# english-paper-skim

ライセンス: コード(`scripts/`、`tests/`)は AGPL-3.0-or-later(`LICENSE`)、文書(`.md`、SKILL.md を含む)は CC BY-NC 4.0(`LICENSE-docs.txt`)。GitHub が正式なライセンス名として認識するのはコード側の AGPL で、文書側は `LICENSE-docs.txt` を読むこと。SKILL.md も文書なので、skill 全体としては非営利の条件（NC）がかかる。著作権者 Kokonoha。

これは、開発者、研究者、エンジニア支援の skill である。

ソフトウェア開発、論文作成、特許申請など、論文の引用をする際、AIに論文を探してきてもらう必要がある。その際、多くのAIはアブストラクトだけを読みもってくるので、全文を通読させる必要もしくは要約をしてもらう必要があるが、取りこぼしが多い。
よって、日本の受験生なら知っているテクニック、英語長文読解でつかうテクニックから着想を得て、その論文の重要な論点、結論、留保、定義、資料などをAIに、"より"節約させたトークンで取得させる目的でこのスキルは開発された。

語によってトークンの節約を図るという手法は他に私は見つけられなかった。見つけた方からの報告を歓迎する。

またこれはα版である。自分にとって役立つレベルとなったので一時開発を止めた。他の分野の研究者、開発者、エンジニアによる他言語および他ドメインでの論文で効かせるための情報提供は歓迎する。

## 使い方

```
python3 scripts/skeleton.py <arXiv の番号 | URL | file.html | file.xml | file.txt | file.pdf | file.md>
```

理解できなかったら、次へ広げる：語（`--word "<語>"`）→ 段落（`--paragraph`）→ 節（`--section`）→ 章（`--chapter`）→ 結論の章（`--conclusion`）→ 要旨（`--abstract`）→ 全文。

番号付きの断章でできた本は `--fragments`、`--fragment <番号>`。見出しの無い利益相反の候補も見るときは `--coi-scan`。

詳しくは `SKILL.md` と `references/詳しい記録.md`。試験は `python3 -B tests/regression.py`。

## 取り出すもの

題、分野の候補、要旨の最後の二文、導入の最後の段落、結論の段落、そして目印の言葉で拾った文：主張、新しさ・対比、残っていること（留保）、定義、資料（データ・コード・出典）、論証（反論と応答）、構成、帰結。ほかに、AI の使用と利益相反。英語の論文と、Markdown の見出しで章立てした日本語の論文に対応する。

## 限界

* 骨は読む入口である。骨だけで、論文の主張、否定、利益相反を確定しない。必ず原文で確かめる。
* 抽出は、見出しと語の照らし合わせによる。抽出の精度を、実際の論文で固定の入力と期待する出力を作って確かめたわけではない。
* 外の人が出す URL を自動で読むサービスには、そのまま使わない（取得先の確かめが無い）。
* 著作権のある論文や本では、骨を長く写して配らない。

## 近いもの

目的や手法の近いものはある。トークンの節約を目的に、要旨と見出しから読む範囲を絞る mcp-ads-arxiv と arxiv-mcp-server。文の役割を、位置と定型の表現で分ける Argumentative Zoning（Teufel と Moens、2002）。主張や限界の目印の正規表現の辞書を持つ contentanalysis（R）。抽出する位置、分類、広げる順番を全部そろえた同じ設計は、2026-10-05 の調査の範囲では見つからなかった。
