# 英語論文の骨読み（english-paper-skim）

## なぜこう読むのか

論文は書き方の型が決まっている。新しさは「However / In contrast / Unlike」の直後に、主張は「We show / Here we present」に、残っていることは「remains unknown / open question / limitation」に、ほぼ必ず書かれる。だから、目を止める言葉と場所を先に決めておけば、全部を読まなくても骨が取れる。全文を読むより、ずっと少ないトークンで済む。

式の正しさは確かめない。査読済みならそこは査読者に預け、未査読（arXiv など）なら「未査読」と必ず書く。

## 手順

1. 本文を手に入れる。arXiv なら HTML 版（`https://arxiv.org/html/<ID>`）が読みやすい。PDF しかなければ `pdftotext` で文字にする。
2. 骨を取り出す：

   ```
   python3 scripts/skeleton.py <arXivのID か URL か、ローカルの .html / .txt / .pdf>
   ```

   出力（Markdown）には、題、要旨の最後の二文、導入の最後の段落、結論の最初と最後の段落、目印の言葉を含む文（種類ごと）、謝辞の中のAIの使用、利益相反、が並ぶ。
3. 骨だけで答えられるなら、全文は開かない。理解できないところがあれば、**語 → 段落 → 節 → 章 → 結論の章 → 要旨 → 全文** の順に広げる。矢印は「理解できなかったら、次へ」の意味で、理解できたらそこで止まる。
   - 語：その語の出てくる文だけ（最大 8 文）：`python3 scripts/skeleton.py <同じ入力> --word "<語>"`
   - 段落：その語を含む段落：`--paragraph "<骨に出た文の一部や語>"`
   - 節（いちばん小さい見出しの単位。例：1.1、または番号の無い Methods など）：`--section "<語>"`
   - 章（いちばん上の見出しの単位。例：1）：`--chapter "<語>"`
   - 結論の章（Discussion / Conclusion を丸ごと）：`--conclusion`
   - 要旨を丸ごと：`--abstract`（日本語の論文でも使える）
   - 全文を開くのは、それでも理解できないときだけ。
   - 見出しが見つからず節の境目が分からないときは、スクリプトがそう書いて、語を含む段落だけを返す。
4. 下の形で、日本語で報告する。

## 報告の形

```
**何の論文か**：著者、所属、arXiv の番号と日付、査読済みか未査読か。
**何を示したか**：We show / We present などの文から。
**何が新しいか**：However / In contrast / Unlike などの文から、先行研究との違い。
**何が残っているか**：remains unknown / open question / limitation / future work などの文から。
**目を引いたところ**：謝辞の AI の使用、利益相反、データやコードの公開。
```

## 気をつけること

- 骨読みで分かるのは、論文が何を主張しているかまで。主張が正しいかは分からない。そう書く。
- 紹介文や宣伝の文と、論文自身の主張を混ぜない。紹介文のほうが大きく言っていることが多い。
- 引用は短く（一文の一部まで）。あとは自分の言葉で言い換える。
- 目印の言葉が一つも拾えない論文（型の崩れた論文、総説など）は、骨読みが効かない。そのときは、その旨を書いて、要旨と結論だけ読む。
- 結論の見出しが標準でない報告（"Recommendations" で終わる、途中に "Discussion" の小節がある、など）では、「結論の最初の段落」を取り違えることがある。骨の結論の段落が前後とつながらないときは、`--conclusion` か `--chapter` で確かめる。

見出しの番号は、算用数字（1、2…）でもローマ数字（I、II…）でもよい。結論の見出し（Discussion / Conclusion）が無い論文では、本文の最後の章を結論の章とみなす（骨の見出しにそう書く）。HTML 版に題の見出しが無い論文は、arXiv の番号や URL を渡せば、要旨のページから題を取る。

受け身で書く論文（"is formalized"、"is presented"）や、"This paper presents" で主張を書く論文にも対応している。

哲学のように、主張と反論と応答が本文の全体に散らばる論文のために、「論証（反論と応答）」の目印だけは、骨の場所に限らず全文から拾う。arXiv で HTML 版が無い論文は、PDF に切り替えて読む。

| 文学、歴史学 | PDF、英語以外の論文 | **効きにくい**。章立てが IMRaD でない、ページの見出しや所属が本文に混じる、英語以外は目印の言葉が拾えない |

英語以外の論文（スペイン語、インドネシア語、ロシア語など）では、目印の言葉が無いので骨読みは効かない。PDF は、ページの上下の見出しが混じって、題や結論の章を取り違えやすい。HTML か全文 XML が手に入るなら、そちらを使う。

**本文かどうかを先に確かめる**：取った HTML に Introduction や Conclusion の語が無ければ、それは論文の本文ではなく、雑誌のサイトの案内ページのことがある。その場合は、PDF の全文を探す。

## 目印の言葉の一覧

`scripts/skeleton.py` の中の `MARKERS` に、種類ごとにまとめてある（新しさ・対比、主張、残っていること、帰結）。足りない言葉に気づいたら、そこに足す。

## 日本語の論文

Markdown の見出し（#）で章立てされた日本語の論文は、自動で日本語の道に入る（本文の 15% 以上が日本語のとき）。

- 取り出すもの：題、要旨の最後の二文、導入の最初と最後の段落、結論の段落（「結論」「おわりに」「まとめ」の見出し。無ければ「考察」、それも無ければ最後の章）、章立ての一覧、日本語の目印を含む文。
- 日本語の目印：主張（本稿は、本稿では、と定義する、と呼ぶ、を論ずる）、新しさ・対比（しかし、一方、ではなく、これに対し、従来）、残っていること（未検証、未確定、今後の課題、決まらない、限界、保留、未実施）、論証（反論、なぜなら、であるならば、のであれば）、帰結（ゆえに、したがって、よって、つまり）。
- 改訂履歴、参考文献、目次は、目印を拾う対象から除く。
- 試した結果（2026-10-05）：長い論文ほど縮む（約 2 万トークンの論文で約 10 分の 1）。短い論文（3,000〜4,000 トークン程度）では、骨は全文の 3 分の 1 くらいで、縮み方は小さい。
- 段落・節を引き出す引数（`--paragraph` など）は、今は英語の論文向けの作り。日本語の論文で足りないときは、章立ての一覧を見て、その章をファイルから直接読む。

## 断章の本（番号付きの断章や箴言でできた本）

番号付きの断章や箴言でできた本のように、導入も結論の章も無く、番号付きの短い断章でできた本は、論文の骨の型に合わない。本文の半分以上が番号付きの断章なら、自動で「断章の本」の道に切り替わる（`--fragments` で明示もできる）。

- 断章の切り方：行の頭の「43.」「§ 43.」のような番号で切る。ページ番号などの雑音を避けるため、番号がほぼ順に進むものだけを採る。PDF は、段組みを保たない読み方（`pdftotext -raw`）も試し、断章がよく取れるほうを使う。
- 出すもの：断章の数と番号の範囲、最初の三つと最後の断章の最初の文、目印（主張・定義、反論と応答〔対話〕、問い、想像の例〔思考実験〕、方法についての言葉）に当たる断章の最初の文を、本の全体から散らして各 6 個。
- 一つの断章を丸ごと読む：`--fragment <番号>`。

試した結果（2026-10-05）：段組みの混ざる、番号付きの断章でできた哲学の本の PDF で、673 個の断章（番号 1〜693）を取り出せた。全文 約 189,000 トークンに対し、骨は 約 1,400 トークン。

## 本について

本は、論文より長く、章立ても違う。主張と反論と応答がはっきりした本では、論文の型の骨でも筋が取れた（全文の 50〜80 分の 1）。著作権のある本では、骨は中で読み、報告は自分の言葉に言い換え、本文を長く写して出さない。

## 読む順番（2026-10-05）

語 → 段落 → 節 → 章 → 結論の章 → 要旨 → 全文。矢印は「理解できなかったら、次へ」の意味。

## 定義と資料の目印（2026-10-05）

README に書いた目的（重要な論点、結論、留保、定義、資料などを取ること）に、スキルの実際を合わせた。英語は「定義」（we define、is defined as、refers to、Definition など）と「資料（データ・コード・出典）」（data are available、github.com、zenodo、doi.org、Data availability、Supplementary など）、日本語は「定義」（と定義する、と呼ぶ、とは、を指す など）と「資料（データ・出典）」（資料、データ、出典、URL、文献の番号 など）を足した。二つは、論証と同じく、本文の全体から拾う。参考文献の一覧は、目印を拾う対象から外す。

## 監査の反映（2026-10-05）

外部の監査の指摘 F1〜F9 を直した。直したあと、監査の再現用の入力と同じ形の入力で、不具合が消えたことを確かめた。

| ID | 指摘 | 直し方 |
|---|---|---|
| F1 | 20 文字以下の文を捨てる（短い否定の文が消える） | 文字の無いものだけを除き、短い文も残す（0835版の監査 I4 で、なお 3 文字以下と日本語の 12 文字以下を捨てていたことが分かり、長さで捨てるのをやめた） |
| F2 | 番号の無い見出しで節の境目を失う | 番号の無い見出し（Introduction、Methods、Results など）も境目にする。導入と結論の終わりにも使う。境目が分からないときは、そう書いて段落だけを返す |
| F3 | 壊れた PDF でも成功で終わる | pdftotext の失敗、空の文字、変換の時間切れ（180 秒）を分けて知らせ、終了コード 2 で止まる |
| F4 | JATS の XML で要旨の見出しを失う | `<abstract>` を「Abstract」の見出しとして残す |
| F5 | 見出しと同じ行の要旨の本文を捨てる | 見出しのあとの本文を残す |
| F6 | 日本語の除外する章の子の見出しの文が混じる | 見出しの深さを覚え、除外する章の子孫も除く |
| F7 | 古い形式の arXiv の URL で例外になる | 古い形式（例 hep-th/9901001）も読む。分からない形は、分かる失敗の文で止まる |
| F8 | いくつもの分類に当てはまる文が先の分類にしか入らない | 分類ごとに重複を数え、それぞれに出す |
| F9 | 最後の章への切り替えが番号のあとのピリオドに対応しない | 「1. Introduction」の形も認める |

条件付きの危険（公開のサービスにするときの話）への手当て：取得量の上限 60MB、PDF の変換の時間の上限 180 秒、一時ファイルを必ず消す、http と https 以外の URL は読まない。ただし、行き先のホストやプライベート IP の確かめは入れていない。外の人や文書から来た URL を自動で読むサービスにするなら、それが要る。

この表の削減量は、作者が試した値（バイトと目安のトークン数が混じる）で、監査では測り直していない。直したあと、前に試した論文で骨の大きさと見出しを比べ、崩れていないことを確かめた（結論の章を、目次の中の見出しではなく本文の結論から取るようになった論文がある）。

## 先行と類似の実装（2026-10-05 の調査より）

出どころ：外部の調査「英語論文骨読みスキルの先行研究と類似実装」（調査の基準日 2026-10-04 UTC）の要約。調査は SKILL.md の設計だけを比べ、`scripts/skeleton.py` そのものは見ていない。GitHub の出どころは特定のコミットに固定されていない。

**目的（トークンやコンテキストの節約）が近いもの**
- **mcp-ads-arxiv**（https://github.com/estevesjh/mcp-ads-arxiv）：トークンの節約をはっきり目的にしている。要旨と見出しを返し、必要な節だけを後から読む。目印の言葉で主張・新しさ・残っていることを抜く骨は、README には無い。
- **arxiv-mcp-server**（https://github.com/blazickjp/arxiv-mcp-server）：論文の本文で会話を圧迫しないことを明記する。要旨で関連を確かめ、節の一覧から関連する節だけ読む。本文の読み出しは既定で 12,000 文字まで。

**手法（位置と目印の言葉）の先例**
- **Argumentative Zoning**（Teufel と Moens、2002）：文の修辞の役割で科学論文を要約する。節や段落の中の位置と、定型の表現のパターンを使う（分類器はナイーブベイズ）。後の AZ-II（2009）は、新しさ、利点、限界、今後の研究を分ける。
- **SumUM**（Saggion と Lapalme、2002）：まず主題を短く示し、読者が選んだ主題を詳しくする。骨から詳細へ広げる先例。
- **contentanalysis**（R の実装、https://github.com/massimoaria/contentanalysis）：主張、対比、限界、今後の研究の正規表現の辞書を持つ。既定では LLM を使う。
- **Paper Plain**（医療論文の理解の支援）：各段落の最初の文をつないで生成モデルに渡す。位置で入力を絞る先例。
- **Scholarcy**：主張、限界、今後の研究、開示事項などを構造化して返す、人向けの読書支援。

**このスキルとの違い（調査の範囲で）**
抽出する位置（要旨の最後の二文、導入の最後の段落、結論の最初と最後）、分類の項目（主張、新しさ、残っていること、論証、構成、AI の使用、利益相反）、広げる順番（段落 → 節 → 章 → 結論の章 → 全文）を、全部そろえた同じ設計は、調査の範囲では見つからなかった。ただし、それは無いことや新しさの証明ではない。

## 分野試験の反映（2026-10-05）

10 分野 20 本で試して見つけた崩れを直した。骨の出力の形と目印の種類は変えていない。直したあと、前に試した 4 本（2609.26742、2610.02145、2411.00986、2308.08708）で骨の出力が一字も変わらないことを確かめた。差分は `変更履歴.md` に要点をまとめてある。

| 崩れ | 直し方 |
|---|---|
| 利益相反の複数形（competing interests、conflicts of interest）を拾えない。20 本中 1 本しか出なかった | 複数形と言い回し（The author declares…no、Duality of Interest、disclosures to declare）を足した。全文に宣言がある 11 本すべてで出る |

| AI の使用が謝辞の外（「AI Use.」の段落）にあると拾えない | 「AI Use」「Use of generative AI」などの節と段落も見る |

## 分野の候補と、見出しの無い利益相反の候補（2026-10-05）

題と要旨から分野の候補を複数出し、その中に利益相反の宣言が慣例の分野があれば、判断を利用者に返す。要旨が無ければ題と 1 章を使い、題も要旨も無ければ推定しない。

- **分野の候補**：分野ごとの語の一覧で機械的に照らし、当たった語の種類の数で、上位 3 つまでを骨の冒頭に出す。何を照らすかは次のとおり。
  - 題と要旨がある：題と要旨。
  - 要旨が無い：題と 1 章（導入。導入が取れなければ最初の番号付きの章）。
  - 題が無く、要旨がある：要旨だけ。
  - 題も要旨も無い：推定しない。分野の判断は利用者に返す。見出しの無い利益相反の候補も出さず、出すかは利用者が決める（`--coi-scan`）。
  - 題は、arXiv の要旨のページ、JATS の article-title、HTML の題の見出しや title から取れたときだけ「ある」と数える。本文の最初の行で埋めた題は、表示には使うが、推定には使わない。分野は、医学・臨床、薬理、生物・分子、心理・精神医学、生態・環境、物理・天文、数学、計算機・AI、経済・経営、社会学・政策、法学、言語学、哲学、宗教・神学、文学・歴史、図書館情報学。推定は語の照らし合わせだけで、当たらないこともある。
- **見出しの無い利益相反の候補**：利益相反の見出しがあれば、今までどおりその下を出す。見出しが無いときは、本文の後ろ 4 割から宣言らしい文を候補として拾う。
  - 分野の候補に、利益相反の宣言が慣例の分野（医学・臨床、薬理、生物・分子、心理・精神医学、生態・環境）があれば、「見出しの無い宣言の候補。宣言として採るかは利用者が判断する」として出す。
  - 無ければ出さず、候補の文の数だけを知らせる。見たいときは `--coi-scan`。
- 背景：分野試験の反映で、見出しの無い宣言を本文の後ろ 4 割から拾うようにしたところ、利益相反の宣言の無い古い本で、本文の「consultant（相談役）」という語を利益相反として 6 文拾った。その本の分野の候補（図書館情報学、社会学・政策、哲学）には宣言が慣例の分野が無いので、今は出さない。医学の論文（シロシビン、PMC13577891）では、見出しの下の宣言がそのまま出る。

## 0835版の監査の反映（2026-10-05）

外部の監査（0835 版が対象）の再現できた 6 件を直した。直したあと、監査の再現資料の合成の入力で、6 件とも期待どおりになった（`tests/regression.py`、全部合格で終了コード 0）。

| ID | 指摘 | 直し方 |
|---|---|---|
| I1 | 章・節が子節の直前で切れる（階層の正規表現の二重エスケープ。前の監査の反映で入れた誤り） | 正規表現を直し、1 / 1.1 / 1.1.1 の深さを 0 / 1 / 2 と数える。章は子節・孫節・兄弟節を含み、次の章を含まない |
| I2 | Main 型の JATS で、要旨が参考文献まで流れ出る | XML（JATS の `<abstract>`、graphical と teaser は除く）と HTML（`ltx_abstract`）の要旨を、要素の境界で取る。平文の見出しから取るのは、それが無いときだけ。要旨の最後の二文から、試験の登録番号や主題の語の行を除く |
| I3 | 利益相反の見出しがあるのに「見出しの無い宣言」と表示し、分野で隠す | 短い行を見出しの終わりとみなす規則をやめ、決まった見出しの語か番号付きの見出しで節を閉じる。見出しがあったか、本文が取れたかを分けて持ち、見出しはあるのに本文が取れないときは、そう書く。同じ直し方を AI の使用の節にも使う |
| I4 | 短い否定・留保（No.、未検証。、保留。）を捨てる | 長さでは捨てない。文字の無いものだけを除く。見出しと同じ行の短い本文も残す |
| I5 | 短い段落・短い行を「見つからない」と返す | 段落と節の探し方から、40 文字超の条件を外す（長いものを優先するが、短いものも拾う） |
| I6 | 小数の階層の断章番号（1.1、1.11）で例外になる | 断章の番号を文字列で扱い、小数の階層も断章にする。`--fragment` に未対応の形を渡したら、説明して止まる |
